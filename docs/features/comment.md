# 機能定義書：コメント（返信を含む）

| 項目 | 内容 |
|---|---|
| 対象の機能 | C-01〜C-05（[機能一覧](../features.md) 1.4）。コメントへのいいねは [like.md](like.md)（L-04） |
| 版 | 0.4（2026-11-14） |

## 1. 概要

投稿にコメントを付ける。自分の投稿にも、**他の人の投稿にも**コメントできる。X と同じく、**コメントにも返信**でき、返信にもさらに返信できる。コメントの一覧からは、コメントした人をフォローできる。

| 用語 | 意味 |
|---|---|
| コメント | 投稿に直接付けたもの |
| 返信 | コメント（または返信）に付けたもの。中身の決まりはコメントと同じ |

## 2. 誰が使えるか

| 機能 | 使える人 |
|---|---|
| コメント・返信をする・一覧を見る | ログインしている人 |
| コメント・返信の削除 | **書いた本人だけ**。サーバーでも本人かを確かめ、他人のものは 404 |

## 3. 入力と制限

| 項目 | 必須 | ルール |
|---|---|---|
| 本文 | ○ | 1〜280文字（投稿と同じ。数え方も [post.md](post.md) 3.1 と同じ）。空白だけは不可。改行は使える |

- 画像は付けられない
- 返信の深さに上限はない（返信の返信の返信…もできる）。表示の仕方は 4.2
- コメント・返信にもいいねできる（[like.md](like.md) 4.4）
- コメントの編集はない（打ち間違えたら消して書き直す）

## 4. 処理の流れ

### 4.1 コメントする（C-01）

1. 投稿の詳細（S-04）の入力欄に本文を入れ、「コメントする」を押す
2. サーバーは入力をチェックし、投稿があるかを確かめてから `comments` に保存する
3. 画面はコメントの一覧の一番下に足し、投稿のコメント数を1つ増やす。入力欄は空にする

### 4.2 コメントの一覧と返信の表示（C-02）

- 投稿の詳細に、投稿への**コメントを古い順**（会話の順）に表示する。50件ずつ「さらに表示」で読み込む
- 返信は、元になったコメントの下に**1段だけ字下げ**して、古い順に並べる
  - 最初は返信を出さず、「返信を表示（3件）」を押すと開く
  - 返信への返信も、同じ段にまとめて並べ、本文の上に「返信先：@ユーザー名」と出す（段を深くしすぎると、スマホで読めなくなるため）
- 1件に出すもの：アイコン・表示名・@ユーザー名・日時・（返信なら）返信先・本文・返信ボタンと返信数・いいね（ハートと数）・フォローボタン・（自分のものなら）削除
- **フォローボタン**（[profile.md](profile.md) 4.3 と同じ部品）：自分のコメントには出さない

### 4.3 コメント数・返信数（C-03）

| 数 | 出す場所 | 数えるもの |
|---|---|---|
| コメント数 | 投稿（タイムライン・投稿の詳細・プロフィール） | 投稿に直接付いたコメントだけ（X と同じ。返信は含めない） |
| 返信数（「↩ 返信 N」） | コメント・返信 | そのコメントに直接付いた返信だけ |
| 返信を表示（N件） | 投稿に直接付いたコメント | その下に並ぶ返信すべて（返信の返信も含む。開いたときに並ぶ数とそろえる） |

### 4.4 削除（C-04）

1. 自分のコメントの「削除」で、確認のダイアログ（M-03）を出す
   - 返信がないとき：「このコメントを削除しますか？」
   - 返信があるとき：「このコメントを削除しますか？ このコメントへの返信も消えます」
2. 「削除する」で、そのコメントと、その下に付いた返信をすべて消す（いいねも一緒に消える）。数を減らす

### 4.5 返信する（C-05）

1. コメント・返信の「返信」ボタンを押すと、そのすぐ下に入力欄を開く。入力欄の上に「返信先：@ユーザー名」と出す
2. 本文を入れて「返信する」を押す
3. サーバーは、返信先のコメントがあり、**同じ投稿のもの**かを確かめてから、返信先を記録して `comments` に保存する
4. 画面は返信の並びの一番下に足し、返信先の返信数を1つ増やす（返信が閉じていたら開く）
5. Esc か「キャンセル」で入力欄を閉じる。入力していたら「編集内容を破棄しますか？」と確かめる

## 5. エラーのとき

| 場面 | 表示する文言 |
|---|---|
| 本文が空 | 「コメントを入力してください」（ボタンを押せなくしておく） |
| 280文字を超えた | 「280文字以内で入力してください」 |
| 投稿が消されていた | 「この投稿は見つかりません」 |
| 返信先のコメントが消されていた | 「返信先のコメントは削除されました」 |
| 送信の失敗 | 「コメントに失敗しました。時間をおいて再度お試しください」（入力した内容は消さない） |

## 6. 関係する画面・テーブル

- 画面：S-04 投稿詳細、M-02 いいねしたユーザー、M-03 確認ダイアログ（[screen-design.md](../screen-design.md)）
- テーブル：`comments`（返信先は `parent_comment_id`、返信が並ぶ一番上のコメントは `root_comment_id`）・`comment_likes`・`users`・`follows`（フォローボタンの状態）

## 7. この文書で新しく決めたこと（確認をお願いします）

- コメントは古い順（会話として読みやすいため）。50件ずつ
- 返信は X と同じく何段でもできるが、表示は1段の字下げにまとめ、「返信先：@ユーザー名」で相手を示す
- 返信は最初は閉じておき、「返信を表示（○件）」で開く
- 投稿のコメント数は、直接のコメントだけを数える（X と同じ）
- コメントを消すと、その下の返信も一緒に消える（X は返信を残すが、作りが複雑になるため）
- コメントの編集はない。投稿の持ち主でも、他人が付けたコメントは消せない
- 返信の数は2つに分ける：「↩ 返信 N」は直接の返信だけ、「返信を表示（N件）」は開いたときに並ぶ返信すべて（2026-11-14、ユーザーの決定。4.3 と画面設計書の図が食い違っていたため）
- 返信は、一番上のコメントの ID（`root_comment_id`）を持つ。返信の返信も同じ ID を持つので、1段にまとめて並べる返信を1回の SQL で読める（2026-11-08、ユーザーの決定）
- 一番上のコメントの下の返信は、続きに分けず、すべてまとめて返す
- 返信先がない・別の投稿のコメントへの返信は、どちらも「返信先のコメントは削除されました」（404）
- 投稿にコメントがないときは「まだコメントはありません」と出す（2026-11-14、画面の実装で決めた）
- 返信の入力欄は一度に1つだけ開く。入力しかけの返信があるときに別の「返信」を押したら、「編集内容を破棄しますか？」と確かめる
- 入力欄の Enter は改行（コメントは改行できる）。送るのはボタンだけ。Esc は、日本語の変換中は「変換をやめる」なので、入力欄を閉じない
- 投稿の 💬（コメント数）を押すと、一覧では投稿の詳細へ、詳細ではコメントの入力欄へ移る
- 一覧（コメント50件・返信）の数（いいね数・自分がいいねしたか・返信の数）は、1回の SQL の中で数える（N+1 問題を起こさない。テストで SQL の回数を数えて確かめている）

## 8. API

すべてログインが必要。POST・DELETE は CSRF トークン（ヘッダー `X-XSRF-TOKEN`）が必要。コメントへのいいねの API は [like.md](like.md) 8章。

| メソッド・URL | 送るもの | 返事 |
|---|---|---|
| GET `/api/posts/{id}/comments?after=` | なし | 200 `{ comments: [Comment], nextAfter }`。投稿への直接のコメントを古い順に50件（返信は入らない）。続きは `after` に `nextAfter` を入れて読む（なければ `null`）／404 `POST_NOT_FOUND` |
| POST `/api/posts/{id}/comments` | `{ content, parentCommentId? }`（返信なら返信先のコメントの ID） | 201 Comment／400 `VALIDATION_ERROR`（`errors[].field` は `content`）／404 `POST_NOT_FOUND`／404 `COMMENT_NOT_FOUND`（返信先がない・別の投稿のコメント。「返信先のコメントは削除されました」） |
| GET `/api/comments/{id}/replies` | なし | 200 `{ replies: [Comment] }`。そのコメントの下に並ぶ返信すべて（返信の返信も含む。古い順）／404 `COMMENT_NOT_FOUND` |
| DELETE `/api/comments/{id}` | なし | 204（下の返信・いいねも消える）／404 `COMMENT_NOT_FOUND`（ない・他人のもの） |

**Comment の形**

| 項目 | 内容 |
|---|---|
| `id` | コメントの ID |
| `postId` | コメントした投稿の ID |
| `parentCommentId` | 返信先のコメントの ID。投稿への直接のコメントなら `null` |
| `rootCommentId` | 返信が並ぶ一番上のコメントの ID。投稿への直接のコメントなら `null` |
| `content` | 本文（前後の空白・改行は取り除いたもの） |
| `createdAt` | コメントした日時 |
| `author` | 書いた人 `{ id, username, displayName }`（メールアドレスは入れない） |
| `replyTo` | 返信先のコメントを書いた人 `{ username }`。直接のコメントなら `null`。画面は、返信への返信（`parentCommentId` が `rootCommentId` と違う）のときに「返信先：@ユーザー名」と出す |
| `mine` | 見ている人のコメントか（画面は `true` のときだけ「削除」を出す） |
| `likeCount`・`liked` | いいね数と、見ている人がいいねしているか |
| `replyCount` | 直接付いた返信の数（「↩ 返信 N」） |
| `threadReplyCount` | 下に並ぶ返信すべての数（「返信を表示（N件）」）。返信なら 0 |

- 他人のコメント・ないコメントの削除は、どちらも 404。本人かどうかは SQL の条件（`WHERE id = ? AND user_id = ?`）で確かめる
- 本文の決まりと数え方は投稿と同じ（サーバーは投稿と同じ部品 `ContentText` で確かめる）。空のときの文言だけ「コメントを入力してください」
- 投稿の返事（[post.md](post.md) 8章の Post）に `commentCount`（直接のコメントの数）がある
