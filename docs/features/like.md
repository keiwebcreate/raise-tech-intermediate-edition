# 機能定義書：いいね

| 項目 | 内容 |
|---|---|
| 対象の機能 | L-01〜L-04（[機能一覧](../features.md) 1.5） |
| 版 | 0.4（2026-11-08） |

## 1. 概要

投稿と、**コメント・返信**に「いいね」を付ける（X と同じ）。自分のものにも、**他の人のものにも**付けられる。いいねした人の一覧からは、その人をフォローできる。

## 2. 誰が使えるか

ログインしている人。

## 3. ルール

| 項目 | ルール |
|---|---|
| 回数 | 1つの投稿に、1人1回まで。DB でも「投稿＋ユーザー」の組が重ならないようにする |
| 取り消し | もう一度押すと取り消す |
| 自分の投稿 | いいねできる（X と同じ） |
| 表示 | いいねしていない：白抜きのハート。いいね済み：赤く塗ったハート |

## 4. 処理の流れ

### 4.1 いいね・取り消し（L-01）

1. ハートを押すと、**画面の表示をすぐに変える**（ハートの色と数）。サーバーの返事を待たないので、押した感じが軽くなる
2. サーバーへ送る。いいねは `likes` に足す、取り消しは `likes` から消す
   - すでにいいね済みのときに「いいね」が届いても、エラーにせず「いいね済み」として扱う（2回押し・同時に押したときに 500 にしない）
3. 失敗したら、画面の表示を元に戻し、「いいねに失敗しました」と出す
4. 連打されても、最後に押した状態になるようにする

### 4.2 いいね数（L-02）

- タイムライン・投稿の詳細・プロフィールの投稿に、ハートと数を出す。0 のときは数を出さない

### 4.3 いいねした人の一覧（L-03）

1. いいね数を押すと、モーダル（M-02）で「いいねしたユーザー」の一覧を開く
2. 新しくいいねした人から順に、20件ずつ（下までスクロールで続き）
3. 1件に出すもの：アイコン・表示名・@ユーザー名・自己紹介（1行まで）・**フォローボタン**（[profile.md](profile.md) 4.3 と同じ部品。自分には出さない）
4. 名前やアイコンを押すと、その人のプロフィールへ

### 4.4 コメント・返信へのいいね（L-04）

- 投稿へのいいねと同じ決まり（3章）と同じ動き（4.1〜4.3）。1つのコメントに1人1回、取り消せる、自分のコメントにもできる
- コメント・返信の下にハートと数を出す。数を押すと、いいねした人の一覧（M-02）を開く
- いいねは `comment_likes` に保存する（投稿のいいね `likes` とは別のテーブル）

## 5. エラーのとき

| 場面 | 表示 |
|---|---|
| いいね・取り消しの失敗 | 表示を元に戻し、「いいねに失敗しました」 |
| 投稿が消されていた | 「この投稿は見つかりません」 |
| コメントが消されていた | 「このコメントは見つかりません」 |

## 6. 関係する画面・テーブル

- 画面：S-03 タイムライン、S-04 投稿詳細、S-05 プロフィール、M-02 いいねしたユーザー（[screen-design.md](../screen-design.md)）
- テーブル：`likes`（投稿）・`comment_likes`（コメント）・`users`・`follows`（フォローボタンの状態）

## 7. この文書で新しく決めたこと（確認をお願いします）

- 自分の投稿にもいいねできる
- 押したらすぐに表示を変え、失敗したら戻す
- いいねした人の一覧は、新しくいいねした順
- コメントのいいねは、投稿のいいねと別のテーブル（`comment_likes`）に持つ
- いいねした人の一覧のフォローボタン・自己紹介と、名前からプロフィールへのリンクは、フォロー・プロフィールの機能のときに足す（ユーザーの決定、2026-11-08）
- いいね数は数の列を持たず、表示のたびに数える（ユーザーの決定）。一覧は、数と「自分がいいねしたか」を含めて SQL 1回で読む（N+1 問題を起こさない。ユーザーの指示）

- 連打したとき：送信は1つずつにし、送っている間に押されたら覚えておく。返事が来たときに最後に押した状態とずれていれば、もう一度送る（押した回数だけ送らない。偶数回押して元に戻ったなら、もう送らない）
- 失敗して戻すときは、サーバーで確かめられた最後の状態に戻す
- いいねした人が0人のときの一覧には「まだいいねはありません」と出す（数が0のときは数のボタンを出さないので、ふつうは開かない）

## 8. API

すべてログインが必要。PUT・DELETE は CSRF トークン（ヘッダー `X-XSRF-TOKEN`）が必要。

| メソッド・URL | 返事 |
|---|---|
| PUT `/api/posts/{id}/like` | 200 `{ liked: true, likeCount }`。もういいねしていても同じ返事（2回押し・同時に押しても 500 にしない。`INSERT … ON CONFLICT DO NOTHING`）／404 `POST_NOT_FOUND` |
| DELETE `/api/posts/{id}/like` | 200 `{ liked: false, likeCount }`。いいねしていなくても同じ返事／404 `POST_NOT_FOUND` |
| GET `/api/posts/{id}/likes?before=` | 200 `{ users: [{ id, username, displayName }], nextBefore }`。新しくいいねした順に20件。続きは `before` に `nextBefore` を入れて読む（なければ `null`）／404 `POST_NOT_FOUND` |

- 「いいねする」を PUT、「取り消す」を DELETE にしたのは、何回送っても結果が同じ（いいねしている／していない状態になる）ようにするため。連打や送り直しで数がずれない
- 投稿の返事（[post.md](post.md) 8章の Post）に `likeCount`（いいね数）と `liked`（見ている人がいいねしているか）がある。タイムラインの20件ぶんも、1回の SQL の中で数える
