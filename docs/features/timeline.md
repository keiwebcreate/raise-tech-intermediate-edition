# 機能定義書：タイムライン

| 項目 | 内容 |
|---|---|
| 対象の機能 | TL-01〜TL-04（[機能一覧](../features.md) 1.2） |
| 版 | 0.2（2026-11-08） |

## 1. 概要

投稿を新しい順に並べて表示する、アプリのメインの画面。2つのタブを切り替えて使う。

| タブ | 出す投稿 |
|---|---|
| すべて（TL-01） | フォローしていない人も含め、**全員の投稿** |
| フォロー中（TL-02） | **自分**と、**自分がフォローしている人**の投稿 |

## 2. 誰が使えるか

ログインしている人。

## 3. 表示のルール

| 項目 | ルール |
|---|---|
| 並び順 | 投稿した日時の新しい順（編集しても順番は変わらない） |
| 最初に開くタブ | 前回見ていたタブ（ブラウザに覚えておく）。はじめてのときは「すべて」 |
| 1回に読む件数 | 20件。下までスクロールしたら、次の20件を読み込む（TL-03） |
| 新しい投稿 | 自分が投稿したら、一覧の一番上に足す。他の人の新しい投稿は、**60秒ごとに数を確かめ、タブの上に「新しい投稿 N件」のボタンを出す**。押すと一覧の一番上に足す（3.2）。タブを押し直す・再読み込みでも出る |
| 他の人の編集・削除 | 自動では反映しない。タブを押し直すか再読み込みで反映する |
| 空のとき | すべて：「まだ投稿がありません」。フォロー中：「まだ誰もフォローしていません。『すべて』や検索から、気になる人を探してみましょう」と、検索画面へのリンク |

### 3.1 投稿1件の表示内容（TL-04）

| 項目 | 内容 |
|---|---|
| アイコン | 未設定なら初期のアイコン。押すとプロフィールへ |
| 表示名・@ユーザー名 | 押すとプロフィールへ |
| 投稿日時 | 「3分前」「2時間前」「11月8日」「2025年12月1日」のように表示（要件 N-06）。マウスを乗せると正確な日時 |
| 編集済み | 編集した投稿にだけ「編集済み」 |
| 本文 | 改行をそのまま表示する |
| 画像・動画 | あれば表示。画像は4枚までを並べ、押すと大きく表示。動画は再生ボタン付き（並べ方は [post.md](post.md) 4.2） |
| コメント数 | 吹き出しのアイコン＋数。押すと投稿の詳細へ |
| いいね数 | ハートのアイコン＋数。ハートを押すといいね、数を押すといいねした人の一覧（[like.md](like.md)） |
| 「…」メニュー | 自分の投稿にだけ出す。「編集」「削除」 |

本文やアイコン以外のところを押すと、投稿の詳細（S-04）を開く。

- 画像・動画は、画像・動画の機能（[post.md](post.md) 3.2）を作るときに表示する
- コメント数・いいね数は、コメント・いいねの機能を作るときに表示する（それまでは押せない 0 のアイコンも出さない）

### 3.2 新しい投稿の知らせ（ユーザーの要望・講義の方針）

| 項目 | 決まり |
|---|---|
| 確かめ方 | 画面が **60秒ごと** に、サーバーへ「一覧の一番上の投稿より新しい、自分以外の投稿は何件か」を聞く（ポーリング） |
| 出し方 | 1件以上なら、タブの下に「新しい投稿 N件」（100件以上は「新しい投稿 100件以上」）のボタンを出す。**押したときだけ**一覧の一番上に足す（読んでいる途中で一覧がずれない。X と同じ） |
| 数え方 | 今のタブに合わせる。「フォロー中」タブはフォローしている人の投稿だけ数える。自分の投稿は数えない（自分の投稿はすぐ一番上に足しているため） |
| 止めるとき | ブラウザのタブが隠れている間（別のタブを見ている間など）は聞かない。見えるようになったら、すぐ1回聞く |

**なぜ WebSocket（つながったままで、投稿があるたびにすぐ届く仕組み）を使わないか**
- 届いた投稿をすぐ一覧に出すと、使う人が多いときに、読んでいる途中で一覧がどんどん動いて使いにくい（講義の指摘）。X も「新しい投稿」を押したときに出す
- 60秒ごとに数を聞くだけなら、ふつうの API が1つで済み、ログインの延長の仕組みもそのまま使える。サーバーの台数が増えてもそのまま動く

## 4. 処理の流れ

1. 画面がサーバーに「どちらのタブか」と「どこまで読んだか（最後の投稿）」を送る
2. サーバーは投稿を新しい順に20件と、続きがあるか（`hasMore`）を返す（コメント数・いいね数・自分がいいねしたかは、その機能のときに足す）
   - 「フォロー中」は、`follows` で自分がフォローしている人と自分の投稿だけに絞る
   - 続きの読み込みは「最後に読んだ投稿より古いもの」で探す（途中で新しい投稿が増えても、同じ投稿が2回出たり抜けたりしないようにするため）。同じ時刻の投稿は ID の大きい順
   - サーバーは21件取ってみて、21件目があれば「続きがある」とする
3. 画面は受け取った投稿を一覧の下に足す。`hasMore` が false なら、続きの読み込みをやめる

## 4.1 API

すべてログインが必要。

| メソッド・URL | 返事 |
|---|---|
| GET `/api/posts?tab=all\|following` | 200 `{ posts, hasMore }`（新しい順に20件） |
| GET `/api/posts?tab=…&before={投稿ID}` | 続きの20件（その投稿より古いもの） |
| GET `/api/posts?tab=…&after={投稿ID}` | その投稿より新しいもの（「新しい投稿 N件」を押したとき）。最新の20件まで。もっとあれば `hasMore` が true（画面は一覧を読み直す） |
| GET `/api/posts/new-count?tab=…&after={投稿ID}` | 200 `{ count }`。その投稿より新しい、自分以外の投稿の数（100件で打ち止め）。`after` がなければ全部を数える |

- 投稿1件の形は [post.md](post.md) 8章の Post
- `tab` が all・following 以外は 400（`VALIDATION_ERROR`）。`before` と `after` は同時に使えない（400）

## 7. この文書で新しく決めたこと（確認をお願いします）

- 「フォロー中」タブには自分の投稿も出す（X と同じ）
- 最初に開くタブは前回のタブ（はじめては「すべて」）
- 20件ずつ、スクロールで続きを読む（無限スクロール。講義と同じ）
- 他の人の新しい投稿は、60秒ごとに数を確かめ、「新しい投稿 N件」を押すと出す（3.2。ユーザーの要望と講義の方針で、v0.1 の「自動では出ない」から変えた）
- 「フォロー中」タブの `follows` テーブルは投稿と一緒に作ったが、フォローする画面・API はプロフィール・フォローの機能のときに作る。それまでは自分の投稿だけが出る
