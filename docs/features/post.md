# 機能定義書：投稿（作成・詳細・編集・削除・画像と動画）

| 項目 | 内容 |
|---|---|
| 対象の機能 | P-01〜P-04（[機能一覧](../features.md) 1.3） |
| 版 | 0.5（2026-11-08） |

## 1. 概要

280文字までの文章に、**画像を4枚まで、または動画を1本**付けて投稿する（X と同じ形）。自分の投稿は、あとから編集・削除できる。

## 2. 誰が使えるか

| 機能 | 使える人 |
|---|---|
| 投稿する・詳細を見る | ログインしている人 |
| 編集・削除 | **投稿した本人だけ**。他人の投稿には「…」メニューを出さない。サーバーでも本人かを確かめ、他人の投稿は「見つかりません」（404）にする |

## 3. 入力と制限

| 項目 | 必須 | ルール |
|---|---|---|
| 本文 | ○ | 1〜280文字。前後の空白・改行は取り除いてから数える。空白だけは不可。改行は使える |
| 画像 | | **4枚まで**。1枚ごとに JPEG・PNG・WebP・GIF（動かない1枚目だけ）、5MB まで |
| 動画 | | **1本まで**。MP4（H.264）。100MB まで、長さ2分20秒（140秒）まで |

- **画像と動画は同じ投稿に混ぜない**（画像だけ、動画だけ、どちらもなし、のどれか）。X と同じ
- 画像・動画を選んだら、投稿の前に小さく表示し、1つずつ外せる

### 3.1 文字の数え方

- 見た目の1文字を1文字と数える（ひらがな・漢字・英字・絵文字、どれも1文字）
- 画面・サーバー・DB で同じ数え方にする
- 入力中は、残りの文字数を表示する（要件 N-05）。残り20文字から黄色、超えたら赤でマイナス表示にし、「投稿する」を押せなくする

### 3.2 画像・動画の保存

| 項目 | 画像 | 動画 |
|---|---|---|
| 保存先 | **S3** | **S3** |
| DB | `post_media` に、S3 のキー・種類（画像か動画か）・並び順を入れる（[database-design.md](../database-design.md)） | 同じ |
| 送り方 | **選んだときに**、画面 → サーバー → S3 の一時置き場（`tmp/`）。サーバーが中身を確かめ、縮小してから保存する | 大きいので、**選んだときに画面から S3 の一時置き場へ直接**送る。サーバーは送り先の期限付きの URL（署名付き URL）を作るだけ |
| 確かめること | 中身が本当に画像か（要件 N-28）。写真の位置情報など（Exif）を取り除く | 送られたあとで、サーバーが S3 のファイルの大きさと中身（MP4 か）・長さを確かめる。だめなら S3 から消して断る |
| 縮小・変換 | 写真の向き（Exif の Orientation）を直し、横幅 1600px より大きければ 1600px に縮小（小さい画像は大きくしない）。**すべて WebP で保存**（画質 0.8）。縦×横が 6000万画素を超える画像は、展開する前に断る | しない（送られたまま保存する）。動画の変換の仕組みは作らない |
| キー | サーバーが決める。一時置き場は `tmp/{利用者ID}/{ランダム}.webp`、投稿したら `posts/{年}/{月}/{ランダム}.webp`。利用者が付けたファイル名は使わない | 同じ（`.mp4`） |
| 表示 | S3 は公開しない。サーバーが期限付きの URL を作って画面に渡す | 同じ |

- 画像・動画は、選んだときに S3 の「一時置き場」（`tmp/`）に置く。投稿したら正式な場所（`posts/`）へコピーし、一時置き場のものは消す。投稿しなかったとき（途中でやめた）の残りは、1日たったら自動で消す（S3 のライフサイクルの設定）
- 一時置き場のキーには利用者 ID を入れ、投稿のときに「自分が置いたものか」を確かめる（他人のファイルは使えない）
- 動画は、投稿のときにサーバーが S3 から取り出して確かめる（道具は metadata-extractor）。MP4 か（MOV は断る）、映像が H.264（`avc1`）か、長さが140秒以内か
- S3 から消すのは、DB の保存が決まったあと（コミットのあと）。DB の保存が失敗したときは、コピーしたものを消す
- 開発中・テストでは、S3 の代わりに **Adobe S3Mock**（Docker、ポート 9090）を使う。期限付き URL の署名・期限は確かめない作りなので、期限切れの扱いは AWS で確かめる

## 4. 処理の流れ

### 4.1 投稿する（P-01）

1. タイムラインの上の入力欄、または「投稿する」ボタンで開くモーダル（M-01）に本文を入れる
2. 必要なら「画像」ボタンで画像（4枚まで、まとめて選べる）か、「動画」ボタンで動画を1本選ぶ
   - 画像を選んでいる間は「動画」ボタンを、動画を選んでいる間は「画像」ボタンを押せなくする
   - 画面で種類・大きさ・（動画は）長さを先に確かめ、だめなものは送る前に断る
3. 動画は、選んだときから S3 への送信を始め、進み具合（％）を出す。終わるまで「投稿する」は押せない
4. 「投稿する」で、本文と画像（または送り終えた動画の情報）をサーバーへ送る
5. サーバーは入力をチェックし、画像は S3 に保存、動画は確かめてから正式な場所へ移し、`posts` と `post_media` に保存する
6. 画面はタイムラインの一番上に投稿を足し、「投稿しました」と出す

### 4.2 表示（タイムライン・詳細）

| 数 | 画像の並べ方 |
|---|---|
| 1枚 | 1枚を大きく |
| 2枚 | 左右に2つ |
| 3枚 | 左に1枚大きく、右に2枚 |
| 4枚 | 2×2 |

- 画像を押すと大きく表示し、左右の矢印（キーボードの ← → でも）で他の画像に移る
- 動画は再生ボタン付きで表示する。自動では再生しない。最初の画面（1コマ目）を出しておく

### 4.3 詳細を見る（P-02）

- 投稿を押すと投稿の詳細（S-04）を開く。投稿と、コメントの一覧・入力欄を出す（[comment.md](comment.md)）
- URL は `/posts/{投稿ID}`。消された投稿・ない投稿は「この投稿は見つかりません」

### 4.4 編集する（P-03）

1. 自分の投稿の「…」→「編集」で、本文と画像・動画が入った状態のモーダル（M-01）を開く
2. 本文を直す。画像・動画は、外す・足す（3章の決まりの範囲で）ことができる。並び順は選んだ順
3. 「保存する」でサーバーへ送る。外した画像・動画は S3 からも消す
4. 投稿に「編集済み」と出す。並び順（投稿した日時）は変わらない
5. 保存せずに閉じるときは「編集内容を破棄しますか？」と確かめる

### 4.5 削除する（P-04）

1. 自分の投稿の「…」→「削除」で、確認のダイアログ（M-03）「この投稿を削除しますか？ コメントといいねも消えます」
2. 「削除する」で、投稿・コメント・いいねを消す。画像・動画は S3 からも消す
3. 投稿の詳細で消したときは、タイムラインへ戻る

## 5. エラーのとき

| 場面 | 表示する文言 |
|---|---|
| 本文が空 | 「本文を入力してください」（「投稿する」を押せなくしておく） |
| 280文字を超えた | 「280文字以内で入力してください」 |
| 画像が5枚以上 | 「画像は4枚までです」 |
| 画像と動画を混ぜようとした | 「画像と動画は一緒に投稿できません」 |
| 画像の種類が違う | 「JPEG・PNG・WebP・GIF の画像を選んでください」 |
| 画像が大きすぎる | 「画像は1枚5MBまでです」 |
| 動画の種類が違う | 「MP4 の動画を選んでください」 |
| 動画が大きすぎる・長すぎる | 「動画は100MB・2分20秒までです」 |
| 動画が2本 | 「動画は1本までです」 |
| 画像の縦横が大きすぎる（6000万画素を超える） | 「画像の縦横が大きすぎます」 |
| 送ったはずの画像・動画がない、他人のもの | 「画像・動画が見つかりません。選び直してください」 |
| 動画の送信の失敗 | 「動画の送信に失敗しました」と「もう一度送る」ボタン |
| 画像の送信の失敗（つながらないなど） | 「画像の送信に失敗しました」（その画像は外れるので、選び直す） |
| 他人の投稿・消えた投稿を編集・削除しようとした | 「この投稿は見つかりません」 |
| 送信の失敗 | 「投稿に失敗しました。時間をおいて再度お試しください」（入力した内容は消さない） |

## 7. この文書で新しく決めたこと（確認をお願いします）

- 本文は必須（画像・動画だけの投稿はできない）。テキスト中心の SNS のため
- 画像4枚と動画1本は混ぜない（X と同じ）
- 画像は1枚5MBまで。GIF は動かさない（1枚目だけ）
- 動画は **MP4・100MB・2分20秒まで**。変換しないので、ブラウザで再生できる MP4（H.264）だけにする。iPhone で撮った動画（MOV・HEVC）は、そのままでは受け付けない
  - 変換の仕組み（AWS Elemental MediaConvert など）を入れれば受け付けられるが、作りと費用が増えるので今回は入れない
- 動画は画面から S3 へ直接送る（EC2 を通すと、大きなファイルでサーバーが重くなるため）
- 編集で画像・動画を足したり外したりできる。並び替えはできない（外して選び直す）
- 編集すると「編集済み」と出る。編集の回数や期限の制限はない。前の内容（履歴）は残さない
- 投稿を消すと、コメント・いいね・画像・動画も一緒に消える
- 画像・動画は、文字の投稿とは別のイシューで作る（2回に分ける。ユーザーの決定）
- 画像も動画と同じく、選んだときに一時置き場へ送る（ユーザーの決定）。画像はすべて WebP で保存する（ユーザーの決定）
- 画像の縦×横の上限は 6000万画素（大きな画像でメモリを使い切らせる攻撃を防ぐため。スマートフォンの写真は大きくても5000万画素ほど）
- 編集で `media` を送らないときは、画像・動画を今のまま変えない。空の並び（`[]`）は「すべて外す」
- 画面では、送る前に種類（ファイルの種類の名前）・大きさ・動画の長さ（`<video>` で読む。140秒より長ければ断る）を確かめる。本当の確認はサーバーが中身を見て行う
- 画像を送るのに失敗したときは、その画像を外して「画像の送信に失敗しました」を出す（動画のような「もう一度送る」は付けない。選び直せば済むため）
- 投稿の表示の期限付き URL は1時間で切れる。タイムラインを開いたまま1時間たつと画像・動画が出なくなるので、そのときは再読み込みする（今は自動では取り直さない）

## 8. API

すべてログインが必要。POST・PUT・DELETE は CSRF トークン（ヘッダー `X-XSRF-TOKEN`）が必要。タイムラインの API は [timeline.md](timeline.md) 4.1。

| メソッド・URL | 送るもの | 返事 |
|---|---|---|
| POST `/api/media/images` | multipart の `file`（画像1枚） | 201 `{ key, url }`（`key` は一時置き場のキー、`url` は縮小した画像を見る期限付き URL）／400（`errors[].field` が `file`） |
| POST `/api/media/videos` | `{ size }`（動画の大きさ。バイト） | 201 `{ key, uploadUrl }`（`uploadUrl` へ `PUT`、`Content-Type: video/mp4` で動画を直接送る。期限15分）／400（`errors[].field` が `size`） |
| POST `/api/posts` | `{ content, media? }`（`media` は一時置き場のキーを並べたい順に） | 201 Post／400 `VALIDATION_ERROR`（`errors[].field` が `content` か `media`） |
| GET `/api/posts/{id}` | なし | 200 Post／404 `POST_NOT_FOUND` |
| PUT `/api/posts/{id}` | `{ content, media? }`（残すものは今の `key`、足すものは一時置き場のキー。送らなければ今のまま） | 200 Post（`editedAt` が入る。`createdAt` は変わらない）／400／404 `POST_NOT_FOUND` |
| DELETE `/api/posts/{id}` | なし | 204／404 `POST_NOT_FOUND` |

**Post の形**

| 項目 | 内容 |
|---|---|
| `id` | 投稿の ID |
| `content` | 本文（前後の空白・改行は取り除いたもの） |
| `createdAt` | 投稿した日時（並び順に使う） |
| `editedAt` | 編集した日時。編集していなければ `null` |
| `author` | 投稿した人 `{ id, username, displayName }`（メールアドレスは入れない） |
| `mine` | 見ている人の投稿か（画面は `true` のときだけ「…」メニューを出す） |
| `media` | 画像・動画 `[{ type, key, url }]`（並び順）。`type` は `image` か `video`、`url` は見るための期限付き URL（期限1時間）。なければ `[]` |
| `likeCount` | いいね数（[like.md](like.md)） |
| `liked` | 見ている人がいいねしているか |

- 他人の投稿・ない投稿の編集と削除は、どちらも 404 `POST_NOT_FOUND`（「この投稿は見つかりません」）。本人かどうかは SQL の条件（`WHERE id = ? AND user_id = ?`）で確かめる
- 文字の数え方は、画面は `[...本文].length`、サーバーは Java の `codePointCount`、DB は `varchar(280)`。どれも「コードポイント」（ほとんどの絵文字も1文字）で数えるのでそろう。家族の絵文字のような、いくつかの文字を組み合わせた絵文字は2文字以上に数える
