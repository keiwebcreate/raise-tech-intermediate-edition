# 機能定義書：プロフィール・フォロー

| 項目 | 内容 |
|---|---|
| 対象の機能 | PF-01・PF-02、FL-01〜FL-04（[機能一覧](../features.md) 1.6・1.7） |
| 版 | 0.5（2026-11-15） |

## 1. 概要

ユーザーごとのプロフィールを表示・編集する。他のユーザーをフォローし、フォロー数・フォロワー数とその一覧を見られる。自分をフォローしている人は、すぐにフォローバックできる。

## 2. 誰が使えるか

| 機能 | 使える人 |
|---|---|
| プロフィール・一覧を見る | ログインしている人（誰のプロフィールでも） |
| プロフィールの編集 | 本人だけ |
| フォロー・解除 | ログインしている人。自分自身はフォローできない |

## 3. プロフィール

### 3.1 表示（PF-01）

URL は `/users/{ユーザー名}`。

| 項目 | 内容 |
|---|---|
| アイコン | 未設定なら初期のアイコン |
| 表示名・@ユーザー名 | |
| フォローされています | 相手が自分をフォローしているときだけ、ユーザー名の横に小さく出す |
| 自己紹介 | 改行をそのまま表示 |
| 登録した月 | 「2026年11月から利用しています」 |
| フォロー数・フォロワー数 | 「12 フォロー」「34 フォロワー」。押すと一覧（S-07） |
| ボタン | 自分：「プロフィールを編集」。他人：フォローボタン（4.3） |
| 投稿の一覧 | その人の投稿を新しい順に20件ずつ（表示はタイムラインと同じ） |

ないユーザー名なら「このアカウントは存在しません」。

### 3.2 編集（PF-02）

| 項目 | 必須 | ルール |
|---|---|---|
| 表示名 | ○ | 1〜50文字。前後の空白は取り除く |
| 自己紹介 | | 160文字まで。改行は使える |
| アイコン画像 | | JPEG・PNG・WebP。5MB まで。正方形に切り取り、400×400px に縮小して S3 に保存する。「画像を外す」で初期のアイコンに戻せる |

- ユーザー名とメールアドレスは、ここでは変えられない（[authentication.md](authentication.md) 7）
- 「保存する」で保存し、プロフィールへ戻って「プロフィールを更新しました」と出す
- アイコンを差し替え・外したら、前の画像は S3 からも消す
- 保存せずに離れるときは「編集内容を破棄しますか？」と確かめる
  - 「←」・メニュー・ブラウザの「戻る」で離れるときは M-03 を出す。再読み込み・タブを閉じるときは、ブラウザの決まった確認が出る（文言は変えられない）
- アイコンは、画像を選んだらすぐにサーバーへ送り（正方形にして一時置き場へ）、丸の中に出す。送っている間は丸の上にくるくるを出し、「保存する」を押せない
- 入力の誤りは「保存する」を押したときに出し、そのあとは打つたびに出し直す。入力欄の下に「12/50」「40/160」（前後の空白を除いた文字数）

## 4. フォロー

### 4.1 フォロー・解除（FL-01）

1. フォローボタンを押すと、すぐに表示を変える（いいねと同じ。失敗したら戻す）
2. サーバーで `follows` に「誰が（follower）誰を（following）」を足す。解除は消す
   - 自分自身は不可（サーバーでも断る）
   - 2回目のフォローはエラーにせず「フォロー済み」として扱う
3. 解除は、ボタンを押したら「@ユーザー名 さんのフォローを解除しますか？」と確かめてから行う

### 4.2 フォローバック（FL-02）

- 相手が自分をフォローしていて、自分は相手をフォローしていないとき、ボタンの文字を「**フォローバック**」にする
- 押したときの動きは、ふつうのフォローと同じ

### 4.3 フォローボタン（共通の部品）

ユーザーが並ぶところ（プロフィール・フォロー/フォロワーの一覧・検索結果・コメント・いいねした人の一覧）では、すべて同じ部品を使う。

| 状態 | ボタンの文字 | 見た目 |
|---|---|---|
| フォローしていない | フォローする | 塗りつぶし |
| 相手だけが自分をフォローしている | フォローバック | 塗りつぶし |
| フォロー中 | フォロー中（マウスを乗せると「フォロー解除」） | 枠だけ |
| 自分 | （出さない） | |

### 4.4 フォロー数・フォロワー数（FL-03）

- プロフィールに出す。数は毎回 `follows` から数える

### 4.5 フォロー・フォロワーの一覧（FL-04）

- URL は `/users/{ユーザー名}/following`（フォロー中）と `/users/{ユーザー名}/followers`（フォロワー）。2つのタブで切り替える
- 新しくフォローした順に20件ずつ（スクロールで続き）
- 1件に出すもの：アイコン・表示名・@ユーザー名・「フォローされています」・自己紹介（1行まで）・フォローボタン
- 空のとき：「まだ誰もフォローしていません」「まだフォロワーはいません」

## 5. エラーのとき

| 場面 | 表示する文言 |
|---|---|
| 表示名が空 | 「表示名を入力してください」 |
| 自己紹介が160文字を超えた | 「自己紹介は160文字以内で入力してください」 |
| アイコンの種類・大きさ | 「JPEG・PNG・WebP の画像を選んでください」「画像は5MBまでです」 |
| フォロー・解除の失敗 | 表示を元に戻し、「フォローに失敗しました」 |
| ないユーザー | 「このアカウントは存在しません」 |

## 6. 関係する画面・テーブル

- 画面：S-05 プロフィール、S-06 プロフィール編集、S-07 フォロー・フォロワー一覧、M-03 確認ダイアログ（[screen-design.md](../screen-design.md)）
- テーブル：`users`・`follows`・`posts`。アイコンは S3

## 7. この文書で新しく決めたこと（確認をお願いします）

- プロフィールの項目：表示名（50文字）・自己紹介（160文字）・アイコン。ヘッダー画像・場所・Web サイトは作らない
- 「フォローされています」の表示と、「フォローバック」のボタン
- フォロー解除の前に確認を出す（押し間違いを防ぐ）
- 一覧は新しくフォローした順
- アイコンは、選んだときに一時置き場（`tmp/{利用者 ID}/icons/`）へ送り、「保存する」で正式な場所（`icons/`）へ移す（投稿の画像と同じ流れ。2026-11-14）。投稿の画像の一時置き場とは分け、正方形にしていない画像をアイコンに使えないようにする
- アイコンは真ん中を正方形に切り取り、400×400 にそろえる（小さい画像も 400×400 に大きくする）。WebP で保存する（投稿の画像と同じ。Exif は残らない）
- フォロー数・フォロワー数は、プロフィールの機能で数だけ先に出す。押して一覧（S-07）へ移る・フォローボタン・「フォローされています」は、フォローの機能のときに足す（2026-11-14、ユーザーの決定）
- アイコンは、ユーザーが出るすべての場所（投稿・コメント・いいねした人・左のメニュー）に出す（2026-11-14、ユーザーの決定）
- 画面の作り（2026-11-15、プロフィールの画面のとき）
  - アイコンと名前のどちらを押してもプロフィールへ移る。アイコンのリンクは、キーボードの移動と読み上げでは飛ばす（すぐ横の名前のリンクと同じ行き先なので、2回続けて読まれないように）
  - プロフィールの投稿が0件のときは「まだ投稿がありません」
  - 編集を保存したら、プロフィールの「プロフィールを編集」から来たときはひとつ前（そのプロフィール）へ戻る。URL を直接開いたときは自分のプロフィールへ移る
  - 編集を保存したら、左のメニューの名前・アイコンもすぐにそろえる。すでに出ている投稿の名前・アイコンは、読み直したときに変わる
- フォローの API（2026-11-15、フォローのサーバーのとき）
  - 相手は URL のユーザー名で指す（ユーザーの決定。プロフィールの API・画面の URL と同じ）。大文字・小文字は区別しない
  - 自分自身をフォロー・解除しようとしたら 400 `CANNOT_FOLLOW_SELF`「自分自身はフォローできません」（画面は自分にボタンを出さないので、ふつうは起きない。解除も断るのは品質チェックでの決定）
  - フォロー・解除の返事に、相手の今のフォロワー数を入れる（プロフィールの数をそろえるため）
  - 一覧の続きの目印（`nextBefore`）は、フォローの行の ID（いいねした人の一覧と同じ作り）
- フォローの画面（2026-11-15、フォローの画面のとき）
  - 画面の中で同じ人が何か所に出ても（コメント・いいねした人など）、1か所でフォロー・解除したら、ほかの場所のボタンもすぐにそろえる（ユーザーの決定）。別の画面に移って読み直すと、サーバーの値になる
  - 送っている間は、その人のボタンを押せなくする（解除には確認があるので、連打はまず起きない）
  - フォローした直後は、マウスが乗ったままでも「フォロー中」と出す（すぐ「フォロー解除」にしない）。キーボードで選んだときも「フォロー解除」と出す
  - プロフィールでフォロー・解除したら、フォロワー数はサーバーの返事の数にそろえる。自分のプロフィールのフォロー数も、どこかでフォロー・解除したら1つ増やす・減らす
  - 自分のフォロー中の一覧で解除しても、その人は一覧から消さない（「フォローする」に変わるだけ。押し間違えてもすぐ戻せる。読み直すと消える）
  - S-07 の上の帯は、表示名と @ユーザー名。タブを替えても履歴を増やさない（「←」でプロフィールへ戻れる）

## 8. API

すべてログインが必要。PUT・POST は CSRF トークン（ヘッダー `X-XSRF-TOKEN`）が必要。

| メソッド・URL | 送るもの | 返事 |
|---|---|---|
| GET `/api/users/{ユーザー名}` | なし | 200 Profile／404 `USER_NOT_FOUND`（「このアカウントは存在しません」）。ユーザー名は大文字・小文字を区別しない |
| GET `/api/users/{ユーザー名}/posts?before=` | なし | 200 `{ posts: [Post], hasMore }`（[timeline.md](timeline.md) と同じ形。新しい順に20件）／404 `USER_NOT_FOUND` |
| POST `/api/media/icons` | multipart の `file`（JPEG・PNG・WebP、5MB まで） | 201 `{ key, url }`（正方形の 400×400 の WebP にして一時置き場に置く）／400 `VALIDATION_ERROR`（`errors[].field` は `file`。「JPEG・PNG・WebP の画像を選んでください」「画像は5MBまでです」） |
| PUT `/api/users/me` | `{ displayName, bio?, iconKey? }` | 200 Profile／400 `VALIDATION_ERROR`（`errors[].field` は `displayName`・`bio`・`iconKey`） |
| PUT `/api/users/{ユーザー名}/follow` | なし | 200 `{ following: true, followerCount }`（`followerCount` は相手の今のフォロワー数）。もうフォローしていても同じ返事（2回押し・同時に押しても 500 にしない）／400 `CANNOT_FOLLOW_SELF`（「自分自身はフォローできません」）／404 `USER_NOT_FOUND` |
| DELETE `/api/users/{ユーザー名}/follow` | なし | 200 `{ following: false, followerCount }`。フォローしていなくても同じ返事／400 `CANNOT_FOLLOW_SELF`（自分自身）／404 `USER_NOT_FOUND` |
| GET `/api/users/{ユーザー名}/following?before=` | なし | 200 `{ users: [FollowUser], nextBefore }`。その人がフォローしている人を、新しくフォローした順に20件。続きは `before` に `nextBefore` を入れて読む（なければ `null`）／404 `USER_NOT_FOUND` |
| GET `/api/users/{ユーザー名}/followers?before=` | なし | 200 `{ users: [FollowUser], nextBefore }`。その人のフォロワーを、新しくフォローされた順に20件／404 `USER_NOT_FOUND` |

- `iconKey`：今のキー（Profile の `iconKey`）なら「残す」、`/api/media/icons` で送った一時置き場のキーなら「差し替える」、`null` なら「外す」。他人のもの・投稿の画像のキー・もうないものは「画像が見つかりません。選び直してください」
- 編集できるのは本人だけ（URL に人を指定させず、ログインしている本人を変える）
- フォローは「ログインしている本人が」相手をフォローする（URL に指定するのは相手だけ）。フォローを PUT、解除を DELETE にしたのは、何回送っても結果が同じになるようにするため（いいねと同じ）
- フォローの状態（`following`・`followedBy`）は、プロフィール・フォロー中とフォロワーの一覧・いいねした人（[like.md](like.md) 8章）・コメントの `author`（[comment.md](comment.md) 8章）の返事にある。一覧でも SQL は増えない
- 投稿・コメント・いいねした人・ログイン中の本人（`/api/auth/me`）の返事の、ユーザーの形に `iconUrl`（アイコンを見るための期限付き URL。未設定なら `null`）がある。一覧でも SQL は増えない

**Profile の形**

| 項目 | 内容 |
|---|---|
| `id`・`username`・`displayName` | |
| `bio` | 自己紹介。なければ `null` |
| `iconUrl` | アイコンを見るための期限付き URL（期限1時間）。未設定なら `null`（画面は頭文字の丸を出す） |
| `iconKey` | アイコンの S3 のキー。未設定なら `null`（編集で「残す」ときに送り返す） |
| `createdAt` | 登録した日時（「2026年11月から利用しています」） |
| `followingCount`・`followerCount` | フォロー数・フォロワー数 |
| `mine` | 見ている人のプロフィールか（`true` なら「プロフィールを編集」） |
| `following` | 見ている人がこの人をフォローしているか（フォローボタン。4.3） |
| `followedBy` | この人が見ている人をフォローしているか（「フォローされています」・「フォローバック」。4.2） |

**FollowUser の形**（フォロー中・フォロワーの一覧の1人）

| 項目 | 内容 |
|---|---|
| `id`・`username`・`displayName` | |
| `bio` | 自己紹介。なければ `null`（画面は1行まで出す） |
| `iconUrl` | アイコンの期限付き URL。未設定なら `null` |
| `following`・`followedBy` | Profile と同じ（見ている人から見たフォローの状態） |
